## 0. 한눈에 보기

**질문:** 공개 데이터로 파인튜닝한 오픈 임베딩 모델(Qwen3-Embedding-0.6B)이 `text-embedding-3-large`(1536차원 절삭)를 우리 그래프에서 대체할 수 있는가?

**결론 (두 판정을 함께 적는다):**

| 기준 | 판정 | 이유 |
|---|---|---|
| 사전에 정한 규칙을 그대로 적용(골든 55케이스 전체) | **대체 불가** | 답변의 recall(−0.041)과 precision(−0.046)이 노이즈 플로어를 넘어 나빠졌다 |
| 사후 분석(그래프 구조에 정답이 묶인 케이스 1개와 영어 짝을 제외, 53케이스) | **구분되지 않음, 환각률은 개선** | 악화가 전부 그 케이스에서 나왔다. 제외하면 recall −0.003, precision −0.016으로 노이즈이고 환각률은 0.128→0.079로 개선 |

- **파인튜닝 덕분이라고는 말할 수 없다.** 학습 전 Qwen3도 우리 라벨에서 같은 수준이었다(쌍 점수에서 구분되지 않음). 공개 검증에서 크게 오른 점수는 우리 데이터로 옮겨 오지 않았다.
- **"바꾸는 게 낫다"는 뜻이 아니다.** 서버 운영, 전체 재임베딩, 임계값 재스윕, CPU 서빙 속도는 이 실험이 답하지 않는다(별도 결정).

**숫자 한 장 요약**

| 단계 | 재는 것 | 3-large | Qwen3 (학습 전) | Qwen3 (학습, ko) |
|---|---|---|---|---|
| 관문 2 · 쌍 AUC | REFERENCE | 0.742 | 0.815 | 0.797 |
| | DISCUSSED_IN | 0.847 | 0.798 | 0.833 |
| 관문 3 · 연결 precision (가중) | 균등 표본 라벨링 | 0.425 | 측정 안 함 | 0.422 |
| 관문 4 · 답변 (55케이스, recall) | 근거 recall | 0.725 | 측정 안 함 | 0.683 |
| 관문 4 · 답변 (환각률, 낮을수록 좋음) | 근거 없는 문장 비율 | 0.160 | 측정 안 함 | 0.113 |

### 용어 풀이

| 용어 | 뜻 |
|---|---|
| 임베딩 | 글을 숫자 벡터로 바꾼 것. 두 글의 벡터가 가까우면 비슷한 내용으로 본다. 이 프로젝트는 이 유사도로 코드 변경·대화·이슈를 잇는 연결(엣지)을 자동으로 만든다 |
| REFERENCE · DISCUSSED_IN · TRIGGERED_BY | 자동으로 만드는 연결 세 종류. 각각 변경↔대화, 이슈↔대화, 변경↔이슈 |
| 임계값 | 유사도가 이 값 이상일 때만 연결을 만드는 컷 점수 |
| AUC | 관련 있는 쌍과 없는 쌍을 하나씩 뽑았을 때 관련 쌍의 점수가 더 높을 확률. 0.5는 동전 던지기, 1.0은 완벽 |
| NDCG@10 | 질문마다 정답 글이 상위 10개 안에서 얼마나 위에 오는지를 0–1로 매긴 점수 |
| precision / recall | 만든 연결 중 맞는 비율 / 연결돼야 할 것 중 찾은 비율 |
| Recall@k · MRR | 검색에서 정답이 상위 k개에 드는 비율 / 정답이 처음 나오는 순위의 역수 평균 |
| 골든 | 사람이 "이 쌍은 반드시 연결돼야 한다"고 정해 둔 정답지(23쌍). 답변 평가용 골든 질문 55개와는 별개다 |
| 환각률 | 답변 문장 중 근거 없는 문장의 비율 |
| 노이즈 플로어 | 같은 설정을 반복해도 생기는 흔들림. 차이가 이보다 작으면 우연으로 본다 |

### 1.4 판정 기준을 미리 고정한 것

**관문 네 개** — 비용이 큰 단계로 가기 전에 멈출 수 있게 했다.

| 관문 | 판정 | 통과하지 못하면 |
|---|---|---|
| 1 | 쌍 AUC(REFERENCE·DISCUSSED_IN) 상위 모델을 파인튜닝 베이스로 고른다 | — |
| 2 | 파인튜닝 모델·베이스·3-large를 같은 지표로 비교한다 | 둘 다 3-large보다 **확실히** 낮으면(AUC 차이 95% 구간 상한 < 0) 음의 결과로 종료 |
| 3 | 같은 골든 recall에서 균등 표본 precision을 비교한다 | 3-large보다 확실히 낮으면 종료. 차이가 0.12 안쪽이면 "구분 불가" |
| 4 | 답변 평가에서 `AGGREGATE_FLOOR`를 넘는 악화가 없는지 본다 | 악화가 있으면 "대체 불가"로 기록 |

- **새 모델의 임계값은 이렇게 맞춘다:** 골든 히트(13/14·6/6·2/3)를 유지하는 가장 높은 지점. 7월에 모델을 바꾸면서 임계값을 그대로 두자 REFERENCE 엣지가 594개에서 1,315개로 늘고 precision이 나빠졌던 일(커밋 `1992dcb9`)이 이유다.
- **노이즈 플로어(`AGGREGATE_FLOOR`):** recall 0.034 · precision 0.042 · 환각률 0.046 · 사실 정답률 0.040 · 규칙 통과율 0.057.
- **학습 변형은 공개 검증의 NDCG@10 평균으로만 고른다.** 우리 팀 라벨은 고른 모델의 평가에만 쓴다(여러 번 보면 그 라벨에 과적합되기 때문).
- 질의 지시문(Instruct)은 쓰지 않는다. 운영의 연결은 저장된 글끼리 비교해 만들기 때문이고, 1단계도 지시문 없이 쟀다.

## 4. 해석

### 4.1 무엇이 확인됐고 무엇은 아닌가

| 질문 | 답 | 근거 |
|---|---|---|
| Qwen3-0.6B가 쌍 단위로 3-large와 비슷한가 | **그렇다** (구분 불가) | 관문 2, 모든 구간이 0을 지남 |
| 그래프에 만드는 연결이 비슷하게 정확한가 | **그렇다** (구분 불가), 단 연결을 25% 적게 만든다 | 관문 3, 가중 precision 0.425 대 0.422 |
| 그 그래프로 한 답변이 비슷한가 | **사전 기준으로는 아니다, 제외 후에는 그렇다** | 관문 4, 두 판정 |
| 환각률이 낮아졌는가 | **그렇다**, 간신히 플로어를 넘는 수준(0.047 대 0.046) | 관문 4, 55·53케이스 모두 |
| **파인튜닝이 효과가 있었는가** | **확인하지 못했다** | 학습 전 모델과 구분되지 않고, 학습 전 모델의 4단계 평가는 안 했다 |
| 과적합인가 | **그렇게 볼 근거가 없다** | 4.4 |
| 바꾸는 게 이득인가 | **이 실험으로는 모른다** | 서버 운영·CPU 속도·재임베딩은 측정 밖 |

### 4.2 파인튜닝은 왜 우리 데이터에 옮겨 오지 않았나 (가설)

공개 검증에서 REFERENCE가 0.24→0.42(+0.17)로 가장 크게 올랐는데, 우리 라벨에서는 학습 전 0.815와 학습 후 0.797로 그대로다. 확인한 것이 아니라 **설명 가능한 가설**이다.

- **문체가 다르다.** 학습 쌍의 코드 쪽은 코드 줄 그대로이고, 우리 그래프의 변경 쪽은 gpt-4o-mini가 쓴 한국어 요약이다. 운영의 요약은 OpenAI가 만든 글이라 약관 때문에 학습에 쓸 수 없었다.
- **학습 전 모델이 이미 높았다.** 학습 전 Qwen3가 우리 REFERENCE에서 3-large보다 +0.073(구간이 0을 지나지 않음)이라 올릴 여지가 적었다.
- 공개 검증의 학생 팀 프로젝트와 우리 프로젝트는 비슷한 편이지만 같지 않다.
- 이 경우를 위한 보강안(오픈 LLM으로 공개 diff를 한국어로 요약해 쌍을 더해 재학습)이 처음부터 계획에 있었고 실행하지 않았다.

### 4.3 연결 수와 precision — DISCUSSED_IN의 큰 상승을 어떻게 읽나

DISCUSSED_IN precision이 0.632에서 0.921(+0.289, 구간이 0을 지나지 않음)로 오른 것은 가장 큰 개선처럼 보인다. 하지만 **임계값을 0.48에서 0.58로 올려 연결을 덜 만든 결과(92쌍 → 56쌍)일 수 있다.** 쌍 점수 구분력(AUC)은 3-large와 같았다(−0.014). 같은 연결 수에서 비교하지 않았으므로 "모델이 더 낫다"고 말할 수 없다.

- 반대로 REFERENCE는 나아지지 않았다. 두 모델 모두 REFERENCE 연결의 약 60%가 틀렸고, 이는 이미 알려진 품질 문제 그대로다.
- **수확량이 줄었다.** 표본에서 추정한 올바른 연결 수가 274개에서 209개다(REFERENCE 211→153). 다만 구간이 겹쳐 확정할 수 없다. 골든 recall은 같았지만 골든은 23쌍뿐이다.
- 임계값을 "골든 히트를 지키는 가장 높은 지점"으로 정한 것은 사전에 고정한 규칙이다. 같은 연결 수로 맞춘 비교는 하지 않았다.

### 4.4 환각률 개선과 과적합 질문

**과적합이 아닐 이유**

1. **우리 데이터는 학습에 쓰이지 않았다.** 학습·검증 쌍의 출처는 공개 저장소 91개(5개 조직)뿐이고, 우리 프로젝트의 저장소·팀 식별자와 겹치는 것이 없다(이름 기준 확인).
2. **환각은 임베딩이 아니라 답변 모델이 만든다.** 임베딩은 어떤 근거를 찾아 주느냐만 바꾼다. 임베딩이 과적합됐다면 recall·precision이 떨어지는 쪽으로 나타나지, 환각률이 낮아지는 경로는 없다.
3. **저장된 모델은 마지막 에폭이 아니다.** 변형마다 검증 점수가 가장 높은 에폭을 남겼다. ko는 학습 손실이 2.02 → 0.99 → 0.38로 계속 내려가는 동안 검증이 0.6550 → 0.6514 → 0.6505로 정체·하락해(3.3) 외우기가 시작되기 전인 에폭 1(154스텝)의 모델을 썼다.

**개선의 원인은 모른다.** 후보는 파인튜닝, Qwen이라는 모델 자체, 연결 수·임계값·`TOOLS_MIN_CONFIDENCE`의 변화, 우연이다. 가장 그럴듯한 설명은 노이즈 연결이 줄었다는 것이다(연결 수가 줄었고 DISCUSSED_IN precision이 높았으며, 7월 실험에서 노이즈 엣지가 답변 컨텍스트를 오염시켜 지표가 악화된 적이 있다). 다만 증명하지 않았다.

**과적합과 닮은 신호가 있는 곳:** 공개 검증의 이득이 우리 데이터로 옮겨 오지 않은 것은 "공개 데이터의 문체에 맞춰졌다"는 뜻일 수 있다. 하지만 학습 전보다 나빠지지는 않았으므로 일반화 실패일 뿐 손상은 아니다.

### 4.5 타당성을 해치는 것 (한계)

### 4.6 전환을 정한다면 (별도 결정)

실험의 결론은 "대체할 수 있는 수준일 수 있다"이지 "바꿔야 한다"가 아니다. 전환을 고려할 때 남는 과제는 다음과 같다.

- 서버를 직접 운영해야 한다. 모델 메모리 약 1.2–2.4GB(파라미터 수로 계산한 추정)가 더 필요하고, CPU 속도는 재 본 적이 없다.
- 차원이 1536에서 1024로 바뀌어 벡터 인덱스 3개를 새로 만들고 모든 프로젝트를 다시 임베딩해야 한다. 임계값도 다시 스윕해야 한다.
- `DocumentSection`(Notion 문서)은 재임베딩 경로가 없다. 이 그래프에는 문서가 없어 측정하지 못했다.
- 이득은 외부 전송 감소와 외부 의존 감소다. 비용 절감은 거의 없다(임베딩 단가가 낮고 현재 규모가 작다). 변경 요약과 답변 LLM은 계속 OpenAI라 전송이 0이 되지는 않는다.

### 4.7 후속 실험 후보 (선택)

| 실험 | 가리는 것 | 비고 |
|---|---|---|
| **학습 전 Qwen3로 4단계 반복** | 환각률 개선이 파인튜닝 때문인지 | 후보 런과 같은 규모(토큰은 답변 약 10M·채점 약 1.7M). 금액은 단가를 확인하지 못했고 사전 추정은 세트당 약 10달러. 재임베딩 10분 |

### 4.8 절차에서 배운 점

- **학습 시간 추정은 패딩을 포함해 계산한다.** 처리 토큰이 글 길이 합의 3.8배였고, 메모리도 가장 긴 글이 정한다.
- **골든에 그래프 구조가 박힌 케이스가 있다.** 모델을 바꿔 그래프를 다시 만들면 정답이 달라진다. 그런 케이스에는 표시를 하고 러너 직전에 다시 센다.
- **`.env`의 같은 키가 두 번 있으면 뒤의 줄이 이긴다.** 후보 설정을 넣을 때 기존 줄을 바꾸지 않고 추가해 중복이 생겼다.
- **한 번에 하나만 바꾼다는 원칙이 대부분 지켜졌지만**, 임계값·`TOOLS_MIN_CONFIDENCE`·모델이 한꺼번에 바뀐 비교는 원인을 갈라 말하기 어렵다.
- 기준선이 덮어써지는 실험은 후보 런을 먼저 하고 복원 뒤 기준선 런을 하는 순서였다. 후보 그래프 덤프는 권한 문제로 건너뛰었다(재구축이 싸고 결정적).
