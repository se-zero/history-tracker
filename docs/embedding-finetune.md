# 임베딩 대체 실험 — text-embedding-3-large → 파인튜닝한 오픈 모델

> **상태: 진행 중** (브랜치 `feat/embedding-finetune`, 2026-11-03 착수). 관문 4까지 측정을 마쳤다(2026-11-06). **데이터 중심 총정리는 [embedding-finetune-report.md](embedding-finetune-report.md)에 있다.** 목적은 **실험**이다.
> 프로덕션 설정은 바꾸지 않고, 대체가 안 된다는 결과도 그대로 기록한다.
> 측정 방법의 정본은 [measurement.md](measurement.md), 임베딩 구조의 정본은 [embedding-design.md](embedding-design.md)다.

## 1. 답할 질문과 기준선

**"공개 데이터로 파인튜닝한 오픈 임베딩 모델이 `text-embedding-3-large`(1536차원 절삭)를 대체할 수 있는가?"**

임베딩을 고른 이유는 개선 여지가 이미 측정돼 있기 때문이다. 자동 구축된 시맨틱 엣지의 40% 넘게가 틀린다.
코드 변경 요약 문체와 구어체 대화는 같은 내용이어도 임베딩 공간에서 멀리 떨어진다([embedding-design.md](embedding-design.md)).
그 간극을 우리 도메인의 쌍으로 직접 학습시키는 것이 파인튜닝의 몫이다.

기준선(`eval/results/edge-2026-07-20-3large-tuned.json`, 라벨 257쌍·골든 23쌍):

| | 전체 | REFERENCE | DISCUSSED_IN | TRIGGERED_BY |
|---|---|---|---|---|
| precision | 0.576 | 0.487 | 0.756 | 0.500 |
| recall | 0.913 (21/23) | 13/14 | 6/6 | 2/3 |

## 2. 전제

1. **학습 데이터는 허용 라이선스(MIT·Apache·BSD) 공개 GitHub 저장소만 쓴다.**
   - 고객 데이터는 쓰지 않는다. Slack 심사 제출 문안이 "we do not fine-tune or train any model on Customer Data"다([slack-marketplace.md](slack-marketplace.md)).
   - 팀 스냅샷(`eval/snapshots`)은 **평가 전용**이다. 학습에 섞으면 시험 문제를 미리 보여 주는 셈이 되고, "처음 보는 프로젝트에서도 통하는가"를 잴 수 없다. 고객 데이터로 학습할 수 없는 서비스에서는 그 조건이 곧 실제 운영 상황이기도 하다.
   - GitHub 이용 정책은 공개·비개인 정보의 연구 목적 사용을 허용한다(결과를 출판하면 오픈 액세스 조건). 그래서 작성자 정보는 저장하지 않는다.
2. **OpenAI가 만든 글은 학습 데이터로 쓰지 않는다.** 약관에 "Output으로 OpenAI와 경쟁하는 모델을 개발하지 않는다"는 조항이 있다. gpt-4o-mini의 diff 요약이나 GPT로 합성한 쌍은 쓰지 않는다. 필요하면 GPU에서 돌린 오픈 LLM의 글만 쓴다.
3. **환경변수를 넣지 않으면 지금과 똑같이 동작한다.** ai-engine 변경은 전부 선택 사항이다.

## 3. 실행 환경

| 위치 | 사양 | 하는 일 |
|---|---|---|
| Mac | Apple M4, 메모리 16GB, MPS. 임베딩용 venv는 Python 3.11(`eval/embedding_finetune/.venv`) | 그래프·eval·후보 비교·학습 데이터 수집·임베딩 서버·풀스택 측정 |
| 학교 GPU (gfarm, AstraGo) | 인터랙티브 잡. 이미지 `vs-code:xiilab/astrago:pytorch-23.07-cuda12.1`. GPU MIG 3g.40gb(80GB GPU의 3/7 조각, 메모리 40GB). 저장은 모델 경로 `whycode`(NFS)를 `/mnt/models`에 붙인다 | **학습만** |

- **연결 방식:** GPU 잡 주소는 학교 내부망(`10.10.x.x`)이라 학교 밖 Mac에서는 닿지 않는다(2026-11-03 확인). 그래서 GPU 쪽은 웹 터미널에서 명령을 치고, 파일은 업로드·다운로드로 주고받는다.
- **GPU 쪽 작업 단위:** 파일 3개를 올리고(스크립트 2개, 데이터 1개), 명령 한 줄을 실행하고, 결과 압축 파일 하나를 내려받는다.
- **GPU 환경:** 이미지의 Python 3.10·PyTorch 2.1(NGC 23.07판)은 쓰지 않는다. transformers 5.x가 Python 3.11 이상·PyTorch 2.6 이상을 요구하기 때문이다. 대신 `/mnt/models/venv`에 Python 3.12와 PyTorch 2.6 이상을 설치한다. 잡은 학습할 때만 켠다.

## 4. 흐름과 관문

비용이 큰 단계로 가기 전에 멈출 수 있게 관문을 넷 둔다.

```
0 기준선 고정 → 1 파인튜닝 없는 후보 비교 ─관문1→ 2 데이터·파인튜닝 ─관문2→ 3 ai-engine 스위치
  → 4 풀스택: 엣지 ─관문3→ 답변 품질 ─관문4→ 5 결과 기록
```

| 관문 | 판정 | 통과하지 못하면 |
|---|---|---|
| 1 | 1차 지표(REFERENCE·DISCUSSED_IN AUC) 상위 1~2개를 파인튜닝 베이스로 고른다 | — |
| 2 | 파인튜닝 모델·베이스·3-large를 같은 지표로 비교한다 | 둘 다 3-large보다 확실히 낮으면(AUC 차이 95% 구간 상한 < 0) 음의 결과로 끝낸다 |
| 3 | 같은 골든 recall에서 균등 표본 precision을 비교한다 | 3-large보다 확실히 낮으면 끝낸다. 차이 0.12 안쪽은 "구분 불가" |
| 4 | e2e 골든셋의 `AGGREGATE_FLOOR`를 넘는 악화가 없는지 본다 | 악화가 있으면 "대체 불가"로 기록한다 |

## 5. 단계별 방법

### 0단계 — 기준선 고정

- 7월 덤프는 7월 코드로 만든 것이라, 그대로 비교하면 그 사이 코드 변경까지 모델 효과로 착각한다.
- 그래서 라벨 파일이 가리키는 `graph-2026-07-21.dump`(pid `eb74cbd9…`)를 로드한다.
- [measurement.md](measurement.md) §4.5 (a) 체인을 현행 임계값으로 다시 돌려 **현재 코드 기준선**과 엣지 수를 기록한다.
- `validate_golden.py`로 깨지는 골든 케이스를 제외 집합으로 확정해 이후 모든 비교에 똑같이 적용한다.
- **7월 덤프와 현재 코드의 차이 하나:** 현재 코드는 이슈를 `"{source}:{external_id}"`로 찾는다. 이 방식은 커밋 `723db829`(Issue 계약 소스 중립화)에서 생겼다. 7월 덤프의 이슈 노드에는 `external_id`가 없어서 `/issue-links/build`가 500으로 실패한다. 옛 노드를 채우는 마이그레이션은 없다.
  - 처리: 실험 그래프에서만 Jira 이슈의 `external_id`를 `issue_key`로 채웠다(95건). 7월 빌더가 `issue_key`로 이슈를 찾던 대응을 복원한 것이다.
  - 덤프 원본은 그대로 두었다. 패치한 뒤 체인까지 돌린 상태를 실험 기준 덤프 `eval/snapshots/exp-base-2026-11-03.dump`로 저장했다. 이후 기준선으로 돌아갈 때는 이 덤프를 로드한다.
  - `status_category`도 없지만 영향은 없다. `closedAt`이 없을 때만 쓰는 대체값인데, 완료 이슈 93건에는 `closedAt`이 모두 있다.

### 1단계 — 파인튜닝 없는 후보 비교 (Mac)

| 후보 | 차원 | 입력 상한 | 라이선스 | 메모 |
|---|---|---|---|---|
| `BAAI/bge-m3` | 1024 | 8,192 | MIT | 접두어 불필요 |
| `nlpai-lab/KURE-v1` | 1024 | 8,192 | MIT | bge-m3를 한국어로 파인튜닝한 모델 |
| `Qwen/Qwen3-Embedding-0.6B` | 32~1024 | 32K | Apache-2.0 | 질의 쪽 지시문 권장 |
| `kakaocorp/kanana-2-1.3b-embedding` | 1280 | 4,096 | Kanana Open License | `trust_remote_code` 필요. 리비전을 고정한다 |

- **임베딩 서버** `eval/embedding_finetune/serve.py`:
  - OpenAI 형식의 `POST /v1/embeddings`를 연다. 그래서 eval 스크립트와 ai-engine이 코드 대부분을 그대로 쓴 채 모델만 바꿔 잴 수 있다.
  - 한 프로세스에 모델 하나만 올리고, 요청 모델 이름이 다르면 거절한다. 엉뚱한 라벨로 결과가 기록되는 것을 막기 위해서다.
- **`eval/precheck_embedding_model.py`:** 후보별 `base_url`과 `--only`를 받는다. 재현 검증은 3-large 점수와 현재 그래프 confidence를 대조한다.
- **`eval/precheck_compare.py`:** AUC 차이의 신뢰구간을 낸다. 쌍들이 스레드를 공유하므로 도착 노드 단위로 복원 추출하는 부트스트랩이다.
- **`eval/precheck_retrieval.py`:** 질문으로 검색했을 때 골든 근거가 상위 5·20개에 드는 비율(Recall@k)을 잰다. 실제 도구는 LLM이 고른 키워드와 HNSW를 쓰므로 근사치다.

**판정 기준(미리 고정):**
- 1차 지표는 REFERENCE AUC와 DISCUSSED_IN AUC다. AUC는 관련 쌍과 무관 쌍을 하나씩 뽑았을 때 관련 쌍 점수가 더 높을 확률이다.
- 동일 골든 recall에서의 precision과 검색 Recall@5는 2차 지표다.
- TRIGGERED_BY는 라벨이 15쌍뿐이라 참고만 한다.

### 2단계 — 학습 데이터(Mac)와 파인튜닝(GPU)

수집 도구는 `eval/embedding_finetune/collect_pairs.py`다(`fetch` → `build` → `sample`, 사용법은 같은 폴더 README).

| 쌍 | 앵커 | 짝 | 대응 엣지 | 대상 저장소 |
|---|---|---|---|---|
| 변경↔대화 | 리뷰 댓글이 가리키는 코드 변경 줄(`[추가] \`줄\`` 형식, 댓글 직전 10줄) | 그 리뷰 댓글 | REFERENCE | 전부 |
| 변경↔대화 | PR 제목 | 그 PR의 대화 댓글 | REFERENCE | 제품형 |
| 변경↔이슈 | PR 제목(커밋 제목줄은 2026-11-04에 껐다, 아래) | PR이 가리키는 이슈 제목+본문 | TRIGGERED_BY | 제품형 |
| 이슈↔대화 | 이슈 제목+본문 | 그 이슈의 댓글 | DISCUSSED_IN | 제품형 |

- **앵커를 이렇게 정한 이유(2026-11-03 결정):**
  - 리뷰 댓글 대부분은 미션 저장소(next-step·woowacourse 과제)에 있다. 그 PR 제목은 "3단계 - 구간 추가 기능 리뷰 요청드립니다" 같은 형식 문구다.
  - 커밋 메시지는 내용이 있지만, 리뷰 댓글이 전부 마지막 커밋에 붙어 있어 어느 커밋에 대한 말인지 알 수 없다. 그래서 댓글이 가리키는 코드 줄을 앵커로 쓴다.
  - 운영의 파일 변경 행은 gpt-4o-mini의 한국어 요약이라 학습에 쓸 수 없다(§2). 코드 줄은 그 문체와 다르다. 그래서 관문 2에서 REFERENCE가 오르지 않으면 GPU의 오픈 LLM으로 같은 문체의 요약을 만들어 더해 본다.
  - 커밋 제목줄 앵커는 2026-11-04에 껐다(`build --per-pr-commit-cap 0`, 기본값 3은 그대로다). 표본 10쌍 중 이슈와 같은 사안은 4쌍뿐이었다. PR의 커밋을 무작위로 고르면 "remove console.log", "docs: 내용 추가 완료"처럼 이슈와 무관한 커밋이 자주 뽑힌다. 일부만 거르는 방식으로는 고칠 수 없었다. 커밋이 하나뿐인 PR의 쌍은 317개뿐이고, 웹 편집기 기본 제목("Update README.md")은 6%뿐이다. PR 제목도 같은 문체("feat: …")라 변경↔이슈는 PR 제목 쌍(표본 9/10)으로 배운다.
- **제품형 저장소:** PR이 아니고 봇이 쓰지 않은 이슈가 20건 이상인 저장소다. 미션 저장소는 이슈가 0~2건이다.
- **출처:** 허용 라이선스(MIT·Apache-2.0·BSD) 비포크 저장소다.
  - next-step 36, woowacourse 34, woowacourse-teams 5, daangn 51, toss 24개다(보관 저장소 제외, 2026-11-03 조회).
  - PR은 약 27,300건, 이슈는 약 4,500건이다.
- **정제:**
  - 봇, GitHub Copilot의 AI 리뷰, 앱이 단 댓글을 뺀다. 코드블록·이모지를 뺀 자연어가 20자 미만이거나 인사·확인뿐인 댓글도 뺀다.
  - 사람 계정으로 올라와 봇 판정을 피한 기계 글도 뺀다(2026-11-04 추가).
    - Codecov 보고는 일반 계정 `codecov-commenter`로, Gatsby Cloud 빌드 보고는 삭제된 계정(`ghost`)으로 올라온다. 그래서 GitHub이 봇으로 표시하지 않는다.
    - 거르는 글은 두 종류다. 첫 줄이 정해진 머리글인 글(이 보고서들과 배포 미리보기 알림의 머리글, 예: `## [Codecov](…) Report`, 그리고 AI 리뷰 템플릿 `**Review 2 · Pass**`)과 `Generated with [Claude Code]` 서명이 있는 글이다.
    - 원자료 대화 글 116,397개 중 4,176개가 걸렸고, 전부 이런 글이었다. 서명은 4,000자로 자르기 전의 원문에서 찾는다.
    - 머리글로 시작하지 않는 사람 글은 남는다(예: "codecov recognize only react package ?").
  - `#123`·`HT-12`·URL·커밋 해시를 가린다. 같은 문자열로 맞히는 법을 배우면, 정작 키가 없는 쌍에는 소용이 없기 때문이다.
  - 이메일과 그 저장소 참여자의 `@멘션`은 원자료를 받을 때 가린다. 작성자 필드는 원자료에도 저장하지 않는다.
  - 중복을 제거하고, PR·이슈당 3쌍, 저장소×유형당 2,000쌍의 상한을 둔다.
- **분할:** 저장소 단위로 나눈다. 운영 데이터와 가장 닮은 `woowacourse-teams/2022-dallog`·`2023-hang-log`는 검증 전용이다.
- **수집 도구의 알려진 한계**(2026-11-03 리뷰에서 현행 유지로 정함):
  - 커밋 제목↔이슈 쌍은 PR 제목↔이슈 쌍보다 덜 정확하다. 같은 PR에 끼어 있던 리팩터 커밋도 짝이 된다. → 2026-11-04 표본에서 4/10이라 껐다(위 「앵커를 이렇게 정한 이유」).
  - 다음은 가리지 못한다: 글을 한 번도 쓰지 않은 사람의 `@멘션`, 본문 속 이름, 원자료 캐시의 글 속 아이디(포크 주소 등). 결과 쌍에서는 URL을 통째로 가린다. 2026-11-04 결과에서 짝 글이 가려지지 않은 아이디로 시작하는 쌍은 train의 0.6%(147개)다. 승인만 한 리뷰어처럼 받아 온 글에 작성자로 나오지 않는 사람이 멘션되면 남는다.
  - 중복 제거가 저장소 상한보다 먼저라, 상한으로 잘린 글과 같은 글이 뒤 저장소에서도 빠진다. 대신 train과 val에 같은 글이 섞이지 않는다.
  - "이슈#12"처럼 한글 바로 뒤에 붙은 번호는 이슈 연결에 쓰지 못한다(가림은 된다).
  - secondary rate limit에 걸리면 1차 한도 reset까지 기다린다. 미션 저장소도 제품형 판정을 위해 이슈 목록을 끝까지 받는다(약 250회 추가).
  - 겉모양 문제 두 가지: URL 가림이 마크다운 링크의 닫는 괄호까지 지우고, 빈 줄은 3줄 이상일 때만 2줄로 줄인다. `build`는 원자료 전체를 메모리에 올린다.
- **표본 확인에서 현행 유지로 정한 것**(2026-11-04):
  - 영어 인사와 얇은 답글: 인사·확인 필터가 한국어 문구 위주라 "Thanks for the contribution!!", "Let me review this in this weekend :)" 같은 영어 인사가 남는다. 새 표본 50쌍 중 무관(✗) 2쌍 가운데 1쌍이 이것이다.
  - 표지 없는 AI 글: 2025년 이후 쌍이 train의 14.4%(3,589개)다. 표지가 없으면 AI가 썼는지 가릴 수 없다. 서명이 일부 글에만 붙은 스레드도 있다(예: daangn/stackflow PR #723은 서명이 붙은 답글 2개만 걸리고, 같은 형식의 다른 답글은 남는다). 쌍마다 `created_at`이 있으므로, 날짜로 거른 변형은 묶음 E에서 쌍을 다시 만들지 않고 시험할 수 있다.
  - AI 리뷰 도구에 사람이 남긴 명령·답글(`@coderabbitai resolve` 등 22건 안팎)은 남긴다.
  - 글 속의 비밀번호 같은 문자열은 가리지 않는다(예: 이슈 댓글에 적힌 영상 암호). 이미 공개된 글이고, 데이터는 밖으로 내보내지 않는다.
- **학습**(묶음 E, 도구는 `eval/embedding_finetune/train.py`·`gpu_run.sh`, 사용법은 같은 폴더 README): Sentence Transformers의 `CachedMultipleNegativesRankingLoss`로 학습한다. 한 배치 안에서 짝은 가깝게, 나머지는 멀게 옮기는 학습이다.
  - **설정:**
    - 배치 128(미니배치 32), `NO_DUPLICATES` 샘플러를 쓴다. 배치는 유형 하나에서만 뽑는다. 같은 유형끼리 서로의 오답이 되어 구분이 더 어려워지기 때문이다.
    - bf16, lr 2e-5, warmup 10%, 입력 512토큰, seed 42를 쓴다.
    - 최대 3에폭을 돌리고 에폭마다 val을 재어 가장 좋은 에폭을 남긴다. 저장은 fp16으로 한다.
  - **지시문은 쓰지 않는다**(2026-11-04 결정). 운영의 엣지는 질문↔문서가 아니라 저장된 글끼리 비교해 만든다. 1단계도 지시문 없이 쟀다.
    - 함정이 하나 있다. 평가기(`InformationRetrievalEvaluator`)는 질의를 `encode_query`로 넣는데, 이 함수는 prompt를 주지 않으면(None) 모델의 query 지시문을 자동으로 붙인다.
    - 그래서 평가기에는 `query_prompt=""`를 준다. 같은 문장의 벡터가 지시문 유무로 cosine 0.91까지 달라지는 것을 확인했다.
    - 학습은 학습 인자의 `prompts`가 비어 있으면 붙이지 않고, Mac 서버(`serve.py`)는 `encode`라 붙이지 않는다.
  - **변형은 데이터로 셋이다**(2026-11-04 결정).
    - `all`(24,996쌍), `ko`(한글이 든 쌍, 19,522), `pre2025`(2024년까지의 글, 21,407)다. 변형은 train만 거르고 val은 모두 같다.
    - 한 번의 GPU 실행에서 차례로 돌리고, 1위 모델만 내려받는다.
    - `ko`는 이슈↔댓글이 2,239쌍에서 899쌍으로 줄어든다. 결과를 읽을 때 언어 효과와 데이터 양 효과를 함께 적는다.
  - **고르는 기준은 공개 검증셋 NDCG@10뿐이다.** 유형별 점수의 평균(세 유형 같은 가중)으로 고른다. val은 변경↔대화 49%, 변경↔이슈 45%, 이슈↔대화 5%라 합쳐 재면 이슈↔대화가 반영되지 않는다. 다만 이슈↔대화 val이 96쌍이라 흔들림이 크다.
  - 팀 라벨로 채점하는 것은 고른 1~2개뿐이다. 같은 라벨을 여러 번 보면 그 라벨에 과적합된다.
  - **GPU 환경:** `/mnt/models`에 Python 3.12 venv를 만든다(uv). torch는 2.14.1+cu126이다. 노드 드라이버 버전을 몰라, 최신 torch 2.15.0이 요구하는 CUDA 13(드라이버 580 이상) 대신 드라이버 525 이상에서 도는 빌드를 쓴다. 모델을 저장·로드하는 sentence-transformers 6.2.0·transformers 5.22.1은 Mac과 같다.
- 데이터와 모델은 `eval/embedding_finetune/data|models/`(gitignore)와 GPU의 `/mnt/models`에만 둔다. 외부 업로드는 하지 않는다.

### 3단계 — ai-engine 스위치 (관문 2 통과, 2026-11-05 진행 결정)

`OPENAI_BASE_URL`은 클라이언트가 하나라 chat까지 함께 옮겨 간다. 그래서 임베딩만 다른 서버로 보내는 스위치를 둔다.

| 파일 | 변경 |
|---|---|
| `openai_client.py` | `get_embedding_client()` 추가. `EMBEDDING_BASE_URL`이 비면 기존 클라이언트를 그대로 쓴다(기존 테스트가 그 객체를 패치한다). 값이 있으면 별도 클라이언트를 만들고 `embed()`만 이쪽을 탄다. 공용 코드라 커밋을 분리한다 |
| `graph/embedder.py` | `EMBEDDING_MODEL`·`EMBEDDING_DIMENSIONS`(기본값 현행 `text-embedding-3-large`·1536). 정수가 아니거나 1 미만이면 import에서 실패한다 |
| `graph/schema.py`·`main.py`·`graph/builder.py` | 벡터 인덱스 차원을 같은 값으로 만든다. 새 함수 `ensure_vector_index_dimensions()`가 실제 인덱스 차원과 대조해 어긋나면 `DROP INDEX` 안내와 함께 기동을 실패시킨다 |
| `routers/query.py` | `/query/config`에 `embedding_model`·`embedding_dimensions` 추가. eval 러너가 meta에 자동 기록한다 |
| `infra/docker/docker-compose.yml`·`.env.example` | ai-engine 환경 5개: `EMBEDDING_BASE_URL`·`EMBEDDING_API_KEY`·`EMBEDDING_MODEL`·`EMBEDDING_DIMENSIONS`·`EMBEDDING_TIMEOUT_SECONDS`. 비우면 현행 |

**지금 코드가 조용히 틀리는 지점(조사 결과):**
- 벡터 인덱스는 `IF NOT EXISTS`라 차원이 바뀌어도 옛 인덱스가 남는다.
- Neo4j는 설정 차원과 다른 벡터를 색인하지 않고, 다른 차원으로 질의하면 오류를 낸다.
- 차원이 같은 신·구 벡터가 섞이면 오류 없이 무의미한 점수가 나온다.

**구현 때 정한 것(2026-11-05):**
- 학습한 모델은 `EMBEDDING_DIMENSIONS=1024`다. 임베딩 서버는 `dimensions`가 모델 차원과 같으면 그대로 돌려주고, 크면 400이다.
- `rate_limiter`는 모르는 모델 이름을 tiktoken `o200k_base`로 폴백하고, 서버가 `x-ratelimit-*` 헤더를 안 주면 기본 버킷으로 돈다. 코드 변경이 필요 없다.
- 차원 가드를 `ensure_vector_indexes()` 안에 넣지 않고 별도 함수로 뺐다. 기존 단위 테스트의 가짜 세션이 결과를 읽는 코드를 견디지 못하기 때문이다. 초기화 블록은 어떤 예외든 30번 재시도하므로, 어긋난 채 기동하면 약 60초 뒤에 실패하고 시도마다 경고 로그에 안내가 남는다.
- 재임베딩 청크(200건)가 현행 호출 제한 시간 60초를 넘길 수 있어 `EMBEDDING_TIMEOUT_SECONDS`(기본 60)를 더했다.
- 질의 지시문 접두어 노브는 만들지 않았다. 지시문을 쓰지 않기로 했다.

### 4단계 — 풀스택 측정 (Mac)

같은 그래프·같은 코드·같은 diff 요약에서 **임베딩만 바꿔** 비교한다.
1. **교체:** 기준 덤프(`exp-base-2026-11-03.dump`)에서 시작한다. 벡터 인덱스 DROP → 재기동 → `force=true` 재임베딩 4종 → 4종 모두 `saved == total` 확인. 임베딩 서버는 요청을 하나씩 처리하므로 재임베딩 라우트도 하나씩 부른다(ai-engine 임베딩 호출 제한 시간 60초는 `EMBEDDING_TIMEOUT_SECONDS`로 늘린다). 이벤트 재주입은 쓰지 않는다. 요약 LLM이 다시 돌면 변수가 둘이 되기 때문이다.
2. **임계값 재조정:** 점수 척도가 통째로 바뀌므로 숫자를 그대로 쓰면 비교가 무효다. 7월 교체 때 임계값을 그대로 두자 REFERENCE 엣지가 594→1,315개로 늘었다(커밋 `1992dcb9`).
   - 세 엣지 임계값은 골든 히트(13/14·6/6·2/3)를 유지하는 지점으로 맞춘다.
   - `discussed_in_margin`은 점수 분산 비율로 환산한다.
   - `TOOLS_MIN_CONFIDENCE`는 기준선에서 통과하던 TRIGGERED_BY 비율과 같아지게 맞춘다.
   - 검색 `threshold=0.30`은 그대로 둔다. Neo4j 점수가 `(1+cos)/2`라 사실상 필터가 아니기 때문이다.
3. **균등 표본 라벨링:**
   - 기존 라벨 257쌍은 과거 모델의 엣지에서 뽑은 것이라, 새 모델의 오탐을 보지 못한다.
   - 그래서 두 그래프에서 균등 표본을 뽑고(`sample_edges.py --uniform --per-type 40 --reuse-labels --blind`), 새 쌍만 섞어 모델과 점수를 숨긴 채 라벨링한다(`label_queue.py`).
   - 표본 파일에는 `--graph-snapshot`으로 그래프 이름을 남긴다. 기준선은 `exp-base-2026-11-03.dump`, 후보는 `exp-base-2026-11-03.dump+<모델 라벨>`이다.
4. **답변 품질:** 관문 3을 통과하면 기준선과 후보를 같은 커밋에서 runner 3회 → grader → compare 순으로 돌린다.
5. **복구:** 끝나면 env를 제거하고 백업한 그래프를 복원한다.

## 7. 알고 가는 측정 한계

- **표본이 작다.** 관련 94쌍·무관 157쌍이라, 서로 다른 모델의 AUC 차이는 대략 0.05 안쪽이면 구분하기 어렵다. 판정은 신뢰구간으로 한다.
- **평가 프로젝트가 하나다.** 결과를 다른 팀에 일반화하지 않는다.
- **프롬프트 문구가 점수 척도에 묶여 있다.** 시스템 프롬프트의 "confidence 0.7 미만은 추정 표기"와 영어 프롬프트의 `>= 0.5`는 env를 따르지 않는다. 그래서 e2e를 읽을 때 confidence 분포를 함께 기록한다.
- **입력 절단이 다르다.** 서버는 2,048토큰, 3-large는 8,000토큰이다. 잘린 건수를 기록한다.
- **장치가 다르다.** 후보 비교와 서빙은 Mac(MPS)에서 fp32로, 학습은 GPU에서 한다. 같은 모델은 같은 장치로 비교한다.
