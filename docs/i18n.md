# 다국어(i18n) 준비 메모

**현재 상태**: 앱(제품 본체) UI와 공개 페이지가 같은 ko/en이다. **답 본문은 질문한 언어(한국어·영어)를 따른다**(§5).
언어 상태의 소유자는 `src/i18n/language.tsx`의 `UiLanguageProvider`다(`main.tsx`).
규칙은 §2와 같다 — 명시 선택 localStorage `ht.lang` > `navigator.languages`의 ko 감지 > 영어.
감지 결과는 저장하지 않고, 위치 신호는 쓰지 않는다. `<html lang>`은 이 Provider가 맞추며
랜딩을 벗어나도 `ko`로 되돌리지 않는다. `meta description`만 공개 페이지의
`LandingLanguageProvider`가 언어에 맞춰 갈아끼우고, 그 페이지를 떠날 때 설명문만 한국어
원문으로 되돌린다. 로캘은 `format.ts`가 `uiLocale()`로 읽는다(`ko` → `ko-KR`, `en` → `en-US`).

이 문서는 i18n 계획서가 아니라, **먼저 끝난 시각 표시 작업이 i18n을 위해 세워 둔 계약**을 적는다.
언어를 추가하는 사람이 모르고 깨뜨리기 쉬운 것들이라 코드 주석과 함께 여기에 남긴다.

---

## 1. 로캘과 타임존은 독립된 두 축이다

이번 작업에서 가장 중요한 결정이다. 이 둘을 묶으면 반드시 누군가는 틀린 시각을 본다.

| 축 | 무엇이 정하나 | 코드 |
|---|---|---|
| **로캘**(표기 언어) | UI 언어 설정 | `i18n/language.tsx`의 `uiLocale()` |
| **타임존**(어느 시각) | 사용자 기기 설정 | `Intl.DateTimeFormat`에 `timeZone`을 **주지 않음** |

`formatInstant()`는 로캘만 받고 타임존은 지정하지 않는다. `timeZone`을 생략하면 브라우저가
기기 설정을 자동으로 쓰기 때문이다. 그래서 **언어를 바꿔도 시각은 안 움직이고, 여행을 가면
언어는 그대로인 채 시각만 움직인다.** 이게 의도한 동작이다.

깨지는 시나리오 (언어 기본값을 위치로 정할 때 특히 위험):

- **뉴욕에 사는 한국인** — 언어는 한국어가 편하지만 시각은 뉴욕 시간이어야 한다.
  위치로 언어를 정하면 영어가 기본이 되는데, 그건 언어 문제일 뿐 **시각과는 무관**하다.
- **서울 출장 중인 미국인** — 위치는 서울이지만 한국어를 못 읽는다. 시각은 서울 시간이 맞다.

> **규칙**: 언어 기본값을 위치로 정하더라도, 그 위치 정보를 **시각 표시에 절대 끌어들이지 않는다.**
> 반대로 사용자가 언어를 바꿨다고 시각 표기의 기준 시간대를 바꾸지 않는다.

## 2. 언어 기본값을 정할 때 쓸 수 있는 신호

결정은 아직 안 됐지만, 후보와 한계를 적어 둔다.

| 신호 | 얻는 법 | 한계 |
|---|---|---|
| 브라우저 UI 언어 | `navigator.languages` | 가장 정직한 "읽고 싶은 언어" 신호. 회사 지급 장비가 영어인 경우가 있음 |
| 기기 타임존 | `Intl.DateTimeFormat().resolvedOptions().timeZone` | **위치의 프록시일 뿐 언어의 프록시가 아니다.** 위 두 시나리오에서 그대로 틀림 |
| IP 지오 | 서버(backend)에서 판별 | VPN·해외 사무실에 취약. 서버 왕복 필요 |
| 사용자 명시 선택 | 설정 화면 | 가장 정확. 한 번 고르면 다른 모든 신호보다 우선하고 영속화해야 함 |

권고는 **`navigator.languages` 우선 → 사용자 명시 선택이 있으면 그것이 최우선**이며,
위치(타임존·IP)는 마지막 폴백으로만 쓴다. 위치를 1순위로 쓰면 "한국어 브라우저인데 영어로 뜨는"
경험이 생긴다.

## 3. 단일 교체 지점

로캘은 `clients/web-dashboard/src/i18n/language.tsx`의 `uiLocale()`이 정한다.
`format.ts`는 그 값을 읽고, 호출부에 로캘 문자열을 흩뿌리지 않는다.

- `formatInstant()` — 답변 본문의 자연어 시각. `ko-KR`은 "2026년 3월 12일 오후 5:42",
  `en-US`는 "March 12, 2026 at 5:42 PM". 타임존은 넘기지 않는다.
- `formatRelative()` — 한국어는 "방금 / N분 전 / N시간 전 / N일 전" 그대로다. 영어만 짝이 있다.
  `Intl.RelativeTimeFormat`은 한국어 문장을 바꾸므로 쓰지 않는다.
- `formatTimestamp()` — 로캘 무관(고정 `YYYY-MM-DD HH:mm`). DESIGN.md상 타임스탬프는 라틴
  기술 토큰이라 UI 크롬에서는 일부러 로캘 표기를 쓰지 않는다. **이 함수는 번역 대상이 아니다.**
- `formatCalendarMonthDay()` — `YYYY-MM-DD`를 Date로 파싱하지 않고 월·일만 자른다.
  한국어는 "10월 1일", 영어는 "October 1".

새 포맷터를 추가할 때 **호출부에 로캘 문자열을 흩뿌리지 않는다** — `uiLocale()`을 기본값으로 받는다.

### 3-1. 문서 헤드(`<head>`)는 별개의 교체 지점이다

`uiLocale()`이 덮는 것은 **본문에 렌더되는 값**이다. 검색·공유에 쓰이는 `<head>` 메타는
React 트리 밖에 있어 같은 함수를 타지 않는다. SPA라서 `index.html` 하나가 모든 경로에
그대로 나가고, 거기 박힌 메타는 언어가 하나뿐이다(한국어).

`<html lang>`은 루트 `UiLanguageProvider`가 맞춘다. `meta description`만
`components/landing/LandingLanguageProvider.tsx`가 공개 페이지에서 갈아끼우고, 그 페이지를
떠나면 설명문만 되돌린다. `<html lang>`은 되돌리지 않는다. 영어 문구(`DESCRIPTION_EN`)는
그 파일에, 한국어 문구는 `index.html`에 있다 — 한국어판은 effect가 마운트 시점에 DOM에서
읽어 복원값으로 쓰므로 **두 곳에 복제되지 않는다.**

본문 로캘을 바꿔도 검색 결과의 제목은 한국어로 남는다. 설명문은 공개 페이지에 있는 동안만
언어를 따른다.

- `<title>`은 **아직 한국어 고정이다.** 앱 전체에 `document.title`을 바꾸는 코드가 없어
  정적 값 하나로 간다. 검색 결과에서 제목은 설명문보다 눈에 띄는 자리라, 영어 색인을
  신경 쓰게 되면 여기가 다음 차례다.
- `og:*`·`twitter:*`는 **일부러 손대지 않는다.** 공유 카드를 긁는 크롤러(Slack·카카오·
  LinkedIn)는 JS를 돌리지 않아 `index.html`의 정적 값만 본다. 런타임에 바꿔도 읽는 쪽이 없다.
  (구글은 렌더링된 DOM을 색인하므로 `meta description` 교체는 반영된다 — 그래서 그것만 바꾼다.)

## 4. 서버는 언어도 타임존도 모른다 (그대로 두어야 한다)

ai-engine은 답변 본문·`evidence[*].occurredAt` 모두 **UTC ISO 정준값**만 내보내고,
표시 변환은 전적으로 web-dashboard가 한다(`lib/remarkLocalTime.ts`, `docs/tools.md`).

**예외 하나 — Slack `/why-code` 답변**(2026-09-13). Slack에는 우리 렌더 계층이 없어 backend가
전송 직전에 변환한다(`SlackAnswerTimeLocalizer`, 규칙은 `remarkLocalTime.ts`와 동일). 원칙과
어긋나지 않는 이유는 둘이다. 저장하지 않는다(단발 질의, 변환본은 Slack 메시지로만 나간다).
그리고 답변이 본인에게만 보이는 ephemeral이라 "뷰어 = 질문자"가 항상 성립해, 질문자의 Slack
프로필 시간대(`users.info`의 `tz`) 하나로 충분하다. **로캘은 지금 `Locale.KOREA` 고정**이다. 웹 화면의 로캘은 `ht.lang`을 따르지만 이 Slack
경로는 아직 한국어다. 바꿀 때는 `users.info?include_locale=true`의 `locale`을 쓴다.

이 분업 덕에 **언어가 늘어도 시각 관련 코드는 손댈 게 없다.** 모델이 어떤 언어로 답하든
ISO를 그대로 옮기기만 하면, 클라이언트가 각 사용자의 로캘·타임존으로 그린다.

**하지 말아야 할 것**:

- 서버(ai-engine·backend)에서 시각을 특정 타임존·언어로 포맷해 **저장**하지 않는다.
  저장된 답변이 그 설정에 영구히 묶여, 다른 언어·다른 시간대 사용자에게 되돌릴 수 없다.
  UTC 기준으로 기대값이 적힌 eval 골든셋(`eval/golden/case-43.yaml` 등)도 함께 깨진다.
- `Intl`이 주는 로캘 표준 표기를 손으로 조립하지 않는다. 한국어 "오후 5시 42분"을 만들려면
  `formatToParts`로 한국어 전용 패턴을 짜야 하는데, 로캘이 늘 때마다 그 분기가 늘어난다.
  그래서 CLDR 표준인 **"2026년 3월 12일 오후 5:42"**(en-US는 "March 12, 2026 at 5:42 PM")를 쓴다.

## 5. 답변 언어 (ko/en)

답 본문의 언어 계약은 여기가 정본이다. 실험과 설계 기록은 [answer-language.md](answer-language.md).

답은 질문한 언어를 따른다. ko·en만 지원하고, 요청마다 한 번 정해 그 답을 만드는 데 끝까지 쓴다.

- **누가 정하나.** 모든 질문이 거치는 발화 판별 LLM이 `language`(ko | en | none)를 함께 낸다.
  none이거나 호출이 실패하면 코드 규칙이 정한다. 순서는 이번 질문 → 같은 대화의 최근 사용자 질문 →
  화면 언어 힌트 `ui_language` → 한국어. 그래프에서 노드를 집어 물은 질문도 판별을 거친다 — 잡담
  판정은 버리고(그 노드를 조회한다) 언어만 쓴다.
- **따르지 않는 것.** "영어로 대답해줘" 같은 명시적 요청은 그 문장이 한국어라 한국어로 답한다.
- **지시.** 영어 답은 본 지시 전체 영어판(`agent/prompt_en.py`)을 쓴다. 한국어 지시와 서버가 붙이는
  문구는 글자 그대로다. 근거 인용(`evidence[*].quote`)은 어느 언어로 답하든 원문 그대로다.
- **MCP.** 에이전트가 받는 결과·오류 문구와 프롬프트는 영어 한 벌이다. `explain_commit`만 선택 인자
  `language`(ko | en, 생략하면 ko)로 질문 문장을 고른다. 도구 설명과 서버 안내문은 한·영 병기이고,
  답은 질문한 언어를 따른다고 안내한다.
- **화면.** 로그인 뒤 앱의 글자와 날짜 로캘은 화면 언어를 따른다(§8). 질의 실패 답
  (`metadata.fallback` / `error_type = AI_ENGINE_ERROR`)은 저장본을 그대로 두고 표시만 바꾼다.
- **아직 하지 않은 것.** `ui_language`를 질의에 실어 보내는 연결, Slack 날짜 로캘(`Locale.KOREA`),
  이미 저장된 답·대화의 번역. 언어가 없는 첫 질문(`HT-12?`)은 화면이 영어여도 한국어로 답한다.
  추천 질문과 노드만 첨부한 전송은 문장 자체가 화면 언어라 답도 그 언어가 된다.

시각 규칙은 언어와 무관하게 유지한다. 본문에 ISO 원문을 그대로 두고 날짜를 말로 풀어 쓰지 않는
규칙은 영어 지시에도 있다. 영어로 "March 12"라고 풀어 써도 클라이언트가 변환할 대상을 잃는 건
똑같다. 화면 언어가 영어면 답 안의 시각은 en-US로 그려지고, 가리키는 순간은 기기 시간대 그대로다(§3).

## 6. 시각 표시 계약 (건드릴 때 주의)

`lib/remarkLocalTime.ts`가 지키는 규칙들이다. 리팩토링하다 무심코 깨기 쉽다.

- **날짜 단독(`2026-03-12`)은 변환하지 않는다.** 날짜는 instant가 아니라서 로컬로 옮기면
  음수 오프셋 지역에서 하루가 밀린다.
- **코드블록은 건드리지 않는다.** 커밋 로그·JSON을 통째로 인용한 자리라 원문이어야 한다.
- **인라인 코드는 노드 전체가 타임스탬프 하나일 때만 변환한다.** 모델이 시각을 백틱으로 감싸는
  버릇이 있어서(실측), 전부 건너뛰면 한 문장 안에서 어떤 시각은 변환되고 어떤 건 ISO로 남는다.
- **자동 링크(autolink) 라벨은 변환하지 않는다.** `https://…?from=2026-03-12T08:42:50Z` 같은
  URL은 remark-gfm이 만드는 링크의 표시 텍스트가 곧 href라, 라벨만 바꾸면 href와 어긋난다.
  매칭된 문자열이 부모 링크의 `url`에도 그대로 들어있는지로 판별한다 — `[2026-03-12T08:42:50Z
  로그](https://example.com/x)`처럼 표시 텍스트가 href와 무관한 명시 링크는 그대로 변환 대상이다.
- **`evidence[*].quote`(인용문)는 변환하지 않는다.** 인용 카드는 `Message.tsx`에서 quote를
  마크다운을 거치지 않고 평문으로 렌더하므로 remarkLocalTime을 타지 않는다 — 의도된 것이다.
  quote는 프롬프트상 "요약·번역·재구성 금지, 원문 그대로 인용"이 원칙이고, 서버가
  `_drop_unverified_quotes`로 도구 결과 문자열에 실존하는지 검증한다. 표시를 바꾸면 화면의
  인용문과 검증 대상이 어긋난다. 같은 카드의 날짜(메타데이터, 로컬 변환)와 인용문 속 시각
  (증거 원문, UTC 그대로)은 역할이 달라 표기가 갈리는 게 정상이다.
- `<time datetime="…">`에 **원본 UTC ISO를 보존**한다. 화면 표기가 로컬로 바뀌어도 정준값은 남는다.

## 7. 검증 방법

언어를 추가한 뒤에도 같은 방식으로 확인한다.

```bash
# 다른 타임존으로 브라우저 띄우기
TZ=America/New_York open -na "Google Chrome" --args --user-data-dir=/tmp/tz-test http://localhost:5173
```

- 같은 답변의 시각이 타임존별로 이동하는가 (언어는 그대로여야 한다)
- 언어를 바꿨을 때 시각의 **표기**만 바뀌고 **가리키는 순간**은 그대로인가
- 개발자도구에서 `<time datetime>`에 UTC 원본이 남아 있는가
- 본문 시각과 인용 카드 날짜가 서로 어긋나지 않는가

강한 판별기: **UTC 15시 이후 이벤트**는 KST에서 날짜가 하루 넘어간다(수집 데이터에 104건).
예 — PR #1 오픈 `2026-03-23T15:01:27Z` → KST `3월 24일 오전 12:01`.

## 8. 앱 UI 언어

답 본문(§5)과 별개로, 로그인 뒤 화면 글자를 ko/en으로 나눈 기록이다(2026-10-17).
다국어 라이브러리는 없다. 문장은 컴포넌트 옆 사전에 두고, 한국어는 바꾸기 전의 글자 그대로다.

된 것:

- 언어 상태·`<html lang>`·앱 상단 메뉴(`AppLanguageMenu`). 랜딩 `LanguageMenu`와 `ht.lang`을 공유한다.
- 채팅 크롬, 추천 질문 4장, 노드만 첨부할 때의 질문("첨부한 항목에 대해 설명해줘." / "Explain the attached items.").
  이 문장은 그대로 전송되므로 영어 화면에서는 영어 답이 돌아온다.
- 사이드바, 온보딩, 가입 동의, 소스, 액터, 그래프 확인, 설정, 계정, 외부 앱 동의.
- 날짜 로캘(`uiLocale`)과 상대 시각. 질의 실패 답은 `metadata.fallback` 또는
  `error_type = AI_ENGINE_ERROR`일 때 표시만 바꾼다. 저장본은 한국어 그대로다.
- `OnboardingPage`의 `GITHUB_REAUTHORIZATION_MESSAGE`(`"GitHub reauthorization required."`)는
  서버 판별 문자열이라 비교식을 그대로 둔다. 안내 문장만 번역한다.
- 요금 카드의 기능 문장은 `lib/plans.ts`에 있던 영어를 고른다. 새로 짓지 않는다.

하지 않은 것:

- 질의 요청에 `ui_language`를 실어 보내기. ai-engine은 받을 준비가 되어 있고 backend 필드와
  `AiEngineQueryClient.ask` 스텁은 그대로다. 언어가 없는 첫 질문은 한국어로 답한다.
- Slack 답의 `Locale.KOREA`.
- 모델이 쓴 답, 인용문, 이미 저장된 대화의 번역.
- 서버가 내려주는 임의 오류 문장을 문자열로 맞춰 번역하기.
- `<title>`·`og:*`·`twitter:*`. 크롤러가 JS 없이 읽는 자리다(§3-1).
